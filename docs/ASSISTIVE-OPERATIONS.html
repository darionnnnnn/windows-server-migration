Windows Server Migration · 離線操作手冊

EOS 主機搬移輔助

提供 TS 將舊主機的業務檔案、設定及可重建系統項目搬到新 Windows Server。軟體由使用者安裝；選用新版時仍保留舊設定原路徑的追查方式。所有發現項目預設選取，實際還原仍須審閱及核准。

開始操作

從可信的本輪版本目錄，以具備必要權限的 Windows PowerShell 5.1 或受驗 PowerShell 7 開啟入口。先選角色與工作區，同一作業沿用 PairId。HTML 只呼叫本機 PowerShell 核心，不能直接對遠端主機下指令。

以下工作區路徑與配對識別碼皆為虛構格式示例，不代表實際環境。

.\Start-ServerMigration.ps1 -Workspace 'C:\MigrationDemo\source' -Role Source
.\Start-ServerMigration.ps1 -Workspace 'C:\MigrationDemo\manager' -Role Manager
.\Start-ServerMigration.ps1 -Workspace 'C:\MigrationDemo\target' -Role Target -PairId <配對識別碼>
# Server Core／無瀏覽器環境
.\Start-ServerMigration.ps1 -Action Menu -Workspace 'C:\MigrationDemo\target' -Role Target

畫面上的「操作」選單會顯示動作名稱、所需欄位、影響與下一步。先預覽，填好 typed 欄位，再確認執行。物件欄位若要求 TrustedPath／TrustedSHA256，必須提供可信 JSON 檔及其實際 SHA256；不接受貼入 PowerShell 程式碼。密碼只輸入機密欄位，不放入草稿、Owner、Reason 或 Evidence。

長工作會取得 jobId；建立作業的同一瀏覽器分頁 session 中，sessionStorage 只保存非秘密的作業追蹤 metadata；該分頁在同一 origin 重新載入後可用它查 pending 工作，其他分頁不會共用；不會保存草稿、token 或秘密。reload 會清除僅存於記憶體的表單草稿。若程序重啟改用新 port，origin 隨之改變，舊追蹤資料不會自動沿用；請輸入 OperationId 或在完整作業歷史中尋找。取消是提出取消要求，等待核心到安全邊界後確認；關閉頁面不代表已取消。重啟後未完成工作可能標為 Interrupted，保留 journal 並先檢查再修復。

設定涵蓋、Windows 內建排程與操作紀錄

IIS 完整來源設定在受保護工作區保存，並列出全域、宣告分節、location 及 configSource。網站核准前，相關設定必須有責任人與證據；不能自動處理的設定保留人工程序及原檔引用。整份 applicationHost.config 不直接覆寫目的端。未選網站不阻擋獨立檔案。

Windows 內建排程不能只按 Microsoft 名稱或資料夾判定。先用 OsProvidedCapture 在來源與目的端取得完整 task XML、task／folder 安全設定及主機版本。再以獨立取得的乾淨 Windows／產品基準、來源證明檔及 SHA256，透過 OsProvidedBaseline 保存責任人確認的基準。使用 OsProvidedReview 比較，最後在目的主機本機載入受控配對材料，以 OsProvidedSubmit 重新讀回後明確選 OSProvided 或 Manual。不同 Windows 定義須另行確認；自訂來源、目的缺少或不符基準仍列人工處置。基準確認不等於 Microsoft 驗證、還原成功或業務驗收。

上述材料保持引用，外部來源證明由責任人保存，不由工作區自動清理。來源條目另記已處置／不執行搬入，封存計畫仍保存排除理由與核准時的受保護證據快照；目的端重新驗本機定義，不要求回讀來源端絕對檔案路徑；不會把目的端現有排程冒稱為工具所還原。

軟體比較分別顯示來源與目的端 SID、帳號及版本。唯一產品配對可跨主機 SID；帳號不同會列出人工映射待辦，多個同產品使用者實例則標為不明確。產品存在不代表帳號、權限或業務相容。

正常操作可用 HTML 表單；Server Core 文字備援使用同一 typed 欄位逐欄輸入、預覽及明確確認，不必手製 JSON。進階可信物件材料仍須路徑與 hash。Assistive.Revision、DecisionRevision、currentSelectionRevision 是三個獨立原生 revision，不可相加成單一數值；dataVersion 是 fleet／catalog 實際 bytes 摘要。sourceSelectionRevision 綁定來源 SpecReview；current-selection revision 供 UI CAS 使用。持久紀錄保存執行端 Windows principal、SID、主機與時間；Owner 是責任人聲明，瀏覽器操作不冒稱完成個人登入驗證。

來源端：盤點與保存

  1. 先執行 Inventory（提供必要的 OutputDirectory）盤點來源並匯出可信 inventory；Manager 匯入時用 ImportInventory 提供 Path 與 ExpectedHash；必要時啟用 DeepDiscovery，補登不能可靠辨識的動態腳本、參數、外部服務、可攜軟體及設定檔。
  2. AssistiveEnable 建立輔助選取。所有發現項目預設選取；用 SaveSelection 保存時，每個未選項目都必須附原因。取消選取只改意願，不會刪除已搬檔案。
  3. 確認 IIS 全域／階層設定、site／pool／application／virtual directory 及全部排程 XML、folder、principal、安全與多個 action。無法自動處理的內容保留人工待辦。
  4. 主封包只收來源 C 槽的核准業務檔案與精確控制材料；其他槽交給非 C 工具。IIS／排程指向 D、E 等槽仍須完整搬移，不能因此排除 workload。
  5. 核准後用 EstimatePackage、ExportPackage、CheckPackage。final 搬移須在共同停寫窗口產生 FreezeSource；保留 full base、delta、manifest、journal、backup 與設定原檔。

工具不搬 Windows 系統本體、不自動安裝軟體。Apache／nginx／Tomcat 等產品保留盤點、檔案及設定，提供人工處置，不宣稱有產品專用自動還原。

管理端：把選取變成可核准計畫

  1. 建立來源／目的配對，以 ImportInventory 匯入兩端 inventory（提供 Path 與 ExpectedHash）及來源軟體目錄，再用 AssistiveEnable 初始化輔助操作。核對來源版本、選用版本、目的端觀測版本，三者各自保留。
  2. 逐項 SpecReview → SaveSpecReview，確認檔案 scope、原路徑／生效路徑、帳號與 SID 映射、必要 metadata、required consumers、共享物件影響及人工責任。
  3. GeneralHost 的處置用 DispositionPreview／DispositionSubmit、RequirementReview／RequirementDecisionSubmit。Pending 仍是待處理；必需相依不能單靠改成 NotNeeded 解除。
  4. 確認獨立項目可單獨處理，必要相依仍成套核驗。選取不是 Include 核准；完成必要審閱後再 ApproveMigration。
  5. 交付封包、可信 hash、核准計畫、非 C transfer plan、必要來源原檔與 HTML 文件。工作負載全部在非 C 槽時，C 封包可只有控制材料，不需放入假業務檔案。

來源封存計畫不因目的端選用新版而修改。已封存核准且仍在執行的作業，必須使用核准時的原版工具 bytes 完成或受控回退，不可在執行中熱換工具。本輪新流程重新盤點、核准及建立基線，不直接轉換執行中的 state。

目的端：比較、等待或還原

  1. 全新安裝 Windows Server 可作初始比較基準，但第一次實際觀測標為 FirstObserved；工具不假造「只有 OS」的盤點證據。用 TargetSnapshot 提供 Path 與 ExpectedHash 更新目的端，再 PublishComparison。
  2. 用 SetSoftwareVersion 表示選用版本。預設沿用來源版本；軟體缺少時由使用者手動安裝，工具不保證只還原檔案就能使用。
  3. 選擇 WaitForInstall 會等待；RestoreNow 只允許已就緒的獨立選取項目還原，缺相依者列 DeferredSoftware／人工處置。每次安裝或改版後重新盤點、比較及產生 TargetReceipt。
  4. FilePlacementPreview 列出逐檔占用、檔案／目錄型別衝突、原路徑、生效路徑與 metadata 條件。原設定例如 C:\temp 預設保存原路徑；目的端已有文件時不合併、不覆寫，報告列出無法放置的原路徑／目標路徑與原因。不可為了清除衝突而清空 Windows 或產品共用目錄。
  5. 用 PreparationPreview 取得目前選取與 chosen version 所對應的 RequirementId、ContextHash。負責人實際確認必要環境後，PreparationEvidence 填 evidence 檔／hash、Owner、觀測與到期 UTC，並明確 AckContextReadback。產出的可信證據檔再供 RestorePreview／Restore 等核心動作使用。
  6. 還原前先 RestorePreview，再 Restore，使用同一 manifest/hash、TargetReceipt/hash、target snapshot 與證據。寫入前核心重新檢查，版本或目的端變動會使相關證據失效。舊版證據不能當作新版已準備完成。

新版設定的「保存」與「生效」分開：找到舊設定不代表新版會自動讀取。需人工格式轉換或不透明腳本／Arguments 修改時，照報告逐項處理並提供實際驗證。

已由使用者手動安裝的 Windows 角色，工具只驗證核准角色確實存在，不重裝、不取得其刪除或回退所有權。工具依核准計畫安裝角色若回報 RebootRequired，先按企業程序重啟，再用相同工作區重新預覽及續跑；重啟前不報完成，也不可刪除安裝前基線。

Windows 設定：先預覽再審閱

選 WindowsSettingsPreviewExport，輸入兩端 inventory 實際檔案路徑／hash 與 ReviewWindowsSettings。預覽產生受保護的 JSON 及安全的逐項差異表。工作卡的「使用此預覽準備設定審閱」將完整 SettingId 清單及來源／目的引用帶入 WindowsSettingsSubmit；PreviewHash 必須是 PreviewFileHash 的實際檔案 hash，不能使用語意 PreviewHash。

逐項選擇 KeepTarget、External 或 ReviewedMigration，按要求填 Owner／Reason／Evidence；沒有合法預設時會留空。按鈕只準備表單，不代表核准或自動提交。ExpectedRevision 綁定預覽時的決策版本；他人修改後必須重新預覽，不能用新 revision 強行套用舊差異。機密設定值與原 XML 不直接顯示在工作卡。

非 C 槽與 IIS／排程成套還原

跳板機先用 NonCPeerProof／NonCPhysicalProof 證明兩端分享及實際目的端 state 身分，再 NonCPlan → NonCTransfer。各檔案驗 hash、必要權限／owner／時間／屬性與當輪 freeze；結果透過 NonCImport 匯入 Manager 權威狀態，之後 G 還原消費已驗證的非 C 結果，不能把它當 C payload 再抄一次。

來源 D→目的 C、來源 C→目的 D 都要核准映射及實際磁碟身分。C／非 C 使用同一目的實體資源 registry；別名、不同 Pair 或不同來源映到同一目的時不能各自繞過排他。缺磁碟、斷線、特殊語意未知、未驗 metadata 或錯誤 volume 只阻擋受影響範圍並列待辦。

IIS 与排程先以停止／停用方式建立，依 pool／folder 順序及 typed 設定還原並 readback。目標路徑映射必須傳入網站實體目錄與 task action／WorkingDirectory 等實際 consumer。opaque Arguments 不自動替換。未選 consumer 共用 pool、全域設定或 folder 的影響必須先確認。

IIS 既有全域／階層分節只套用明確審閱的欄位變更，保存目的端原 XML 作受控回復，不整份匯入舊 OS 設定。目的設定漂移或排程目錄安全設定不符時保留原檔、intent 與 journal，先調查並重新核對；不能手改紀錄取得成功。共享排程目錄由實際建立項目持有，回退仍需確認沒有其他排程使用它。

結果、切換與可攜交接

  1. 用 ExportResult 記錄權威 state／journal 與逐項世代；實際目的端內容或 metadata 漂移會使有效路徑及完成狀態失效，歷史成功不代表現在有效。
  2. 同輪 final 資料、C／非 C 相依、必要 evidence 與 CutoverReady 核驗通過後，才 CutoverPlan／Cutover。啟用網站／排程是獨立核准動作；啟用後再由負責人供 BusinessFinal／FinalAccepted。
  3. AssistiveReport 產生完整 HTML bundle、逐檔衝突、原設定索引、軟體差異、人工清單及成套 workload 詳情。用 AssistiveReportCheck 的 DocumentManifestPath／DocumentManifestHash 檢查文件成員完整性。文件 manifest 與封包 manifest 是不同資料，不可互換。
  4. 交付時整個 bundle 一起帶走，用相對連結離線瀏覽；超過 2,000 筆仍提供完整清單，摘要數量需與實際完整資料一致。文件不是還原核准，也不是正式資格證明。

Owner 欄位記錄責任聲明，沒有企業身分驗證或權限委派功能。正式環境須由企業平台、產品與業務責任人核驗；合成測試不能解除正式 production gate。

失敗、續跑與環境探測

部分成功保留逐項 state、journal、原檔與 backup。先 CheckJournal／Repair；delta 要有可信完整 base，缺 base 的項目不能從不存在的目的端補檔。RollbackPreview 列出逐檔 undo 與漂移，再 Rollback；不移走未擁有的整個目錄、不刪人工新增檔案。非 C 資料的 undo 由其已證明的 transfer 邊界處理，不能借 C rollback 宣稱全數回復。

Assistive Restore 取消或中斷後若材料仍被 live job 保留，先確認 restore worker／PowerShell 程序已停止；以相同目的端 StateDirectory、可信封包 ManifestPath 與 ExpectedHash 執行 MaterialJobStatus（Mode=Restore），取得只讀 HTML 報告。先 CheckJournal，再 Repair；pending operation 必須為 0 或已由 Repair 明確對帳，之後重新產生報告。只有人工確認 worker 已停止且最新報告仍顯示相同 RestoreAttempt、PendingOperationCount=0，管理員才可將 JobLock 設為 Active=false，並逐字使用報告中的 MaterialJobOperationId、PairId、Generation、完整 MaterialIds。Status=ReportOnly，LockStatus 才是目前鎖狀態；WorkerStopped 固定為 NotVerified。

NonC worker 中斷後，請用相同 MaterialJobStatus 選擇 Mode=NonCRegistry，提供目的端 StateDirectory、PairId、Generation 與 HTML 輸出路徑。這是 RegistryOnly 報告，只列出該 Pair／generation 的 live operation、完整 MaterialIds 與材料 Kind/hash；PendingOperations 與 WorkerStopped 均為 NotVerified，且報告不驗證 transfer plan、TransferId、目的端、journal 或檔案效果。先確認同一份已審閱 transfer plan 與 TransferId、正確目的端 StateDirectory、所有相關 NonC worker 已停止，並人工對帳 NonC journal 與傳輸效果。之後才可用報告中完全相同的 OperationId、PairId、Generation、MaterialIds 設 JobLock Active=false，再重跑原 transfer plan。若 registry 或材料身分不符，停止並保留資料交由管理員調查。兩種模式都不會自動解鎖、採納工作或修改狀態；不要手改 state／registry JSON，也不要任意解鎖。新登記的同 Pair／generation 材料在該組任何工作仍執行時一律保留。解鎖後重新執行 CleanupPreview，檢查新 revision 與逐項資格，再依保留核准執行 Cleanup。

必要材料未結案、仍有 consumer／活躍工作或尚在回退期限時不得清理。CleanupPreview → Cleanup 必須核對新 revision、相依與明確確認；沒有保留期限／責任核准就保持原材料。請勿手動刪除比較基準、base、delta鏈、receipt、原證據、backup 或 journal。

沒有實機的項目用 EnvironmentProbe 匯出 HTML／JSON，再 ProbeImport 補入探測結果。預設只探測能力，不自動盤點整台 Server；需要完整盤點時明確使用 -CaptureInventory（-DeepDiscovery 亦表示同意盤點），並在本機具管理權限的 Source／Target 執行。盤點可能耗時，完成探測不代表原生還原或業務驗收通過。HttpIntegrityProbe 檢查 loopback 回應與本機靜態資源實際 bytes 是否一致；若企業代理、端點產品修改回應，結果為 ModifiedTransport／NotTested，不把它算橋接通過，也不自動修改企業 policy。Server Core 使用相同核心的文字選單／可信 OperationRequest 備援。

目前小範圍測試只能證明所涵蓋的檔案、契約及 fixture 行為。實機 Windows Server、IIS／排程服務、SMB、特殊檔案、實際帳號存取、業務效能及正式資格以探測與企業補驗結果為準。

進階技術細節（保留英文契約原文）

本節導覽 角色與交接完整流程來源操作管理端審閱目標操作軟體與版本路徑與檔案範圍IIS 與排程工作衝突與部分結果可攜報告與證據驗證與切換疑難處理

階段狀態各自獨立

Discovered（已發現）表示來源盤點看到了項目；Selected（已選取）記錄操作者目前意願；Include / Exclude（納入／排除）是獨立審閱決策。核准封存精確計畫；target receipt 綁定封包、世代、目標快照與選取子集；target journal 記錄寫入與讀回。之後由責任人提供業務驗證。任何一項狀態都不代表下一階段已完成。

角色與交接

來源責任人

確認工作負載及使用端，找出重要檔案與設定，審閱來源路徑範圍並提供協議好的停寫時段。來源責任人不會從來源盤點推論目標已準備完成。

搬移管理人員

審閱所有發現項目、選取、相依、映射、軟體差異、人工待辦與核准，再將可攜報告及需保留的證據交給目標團隊。

目標操作人員與業務負責人

目標操作人員取得目標基準、檢查衝突、準備選定軟體、選擇核准範圍內的還原子集並檢查讀回。業務負責人測試應用程式、核准切換並負責來源退役接受。

Owner 欄位是責任聲明，不會驗證填寫者身分，也不能證明具備企業授權。

完整工作流程

  1. Discover取得不可變來源盤點。首次取得的目標快照標示為觀測資料，不推定目標是全新或乾淨主機。
  2. Select and review新發現項目預設選取；需要調整時明確變更意願。審閱決策與理由仍和選取狀態分開記錄。
  3. Prepare the plan映射精確檔案範圍及型別化工作負載設定，找出共享資源使用端、記錄負責人，並處理所選 Include 集合的前置條件。
  4. Approve and seal核准綁定計畫實際 bytes。相關選取、決策、路徑或設定變更後，必須重新審閱並核准。
  5. Observe target and compare取得目標目前的軟體與工作負載盤點，審閱來源版本、選用版本、目標觀測版本，以及設定和環境差異。
  6. Decide and restore為精確封包世代與允許子集建立目標決策。選擇「等待」不會寫入目標；還原結果會分別列出部分完成、延後、衝突與失敗項目。
  7. Validate and hand over檢查目標端持有的 journal 與讀回結果，完成責任人及業務檢查、記錄切換證據、觀察協議期間，並將來源退役作為獨立接受關卡。

來源主機操作人員

盤點前

  • 確認來源主機身分及 Windows Server 工作負載屬本工具範圍：一般網站、排程工作與支援服務。
  • 以足夠讀取權限執行受支援的本機 PowerShell 盤點流程；記錄範圍不完整與存取失敗項目以便追查。
  • 將原始設定留在受保護工作區。對外報告與草稿畫面不得顯示原始 XML、排程參數、憑證或私鑰。

封存計畫前

  • 審閱已選項目、Include／Exclude 決策、必要相依與共享資源使用端。
  • 來源檔案須明確選擇完整範圍或逐檔審閱集合。主封包涵蓋核准的來源 C: 內容；非 C: 內容走獨立取證的 D 通道。
  • 在來源主機確認磁碟區與通道分流規則，協議由誰停止寫入及如何驗證最終一致性時段。

盤點建議路徑位於 C: 不代表已證實。來源端擷取與封存流程必須確認實體來源範圍。工作負載沒有 C: 資料時，不要為填滿封包而製造假檔案。

管理主機審閱

使用 HTML 審閱完整發現集合，包括不支援或內容不透明的項目。每項都應有明確處置；必要時指定負責人與理由。未選取的待處理項目不一定阻擋獨立已選工作負載，但所選使用端的必要相依或共享資源影響必須先解決。

先比較再選擇版本

軟體表分開呈現來源版本、目標選用版本、首次觀測基準與目前目標觀測版本。來源 hash、目標 hash 與選取 revision 仍相符時，已保存比較才有效；輸入變更後須重新取得並發布比較。

保留審閱歷程

保留舊證據供稽核與復原。來源選取、軟體選擇或相關映射變更後，不重用過期比較或 target receipt；重新審閱受影響範圍並建立新的精確決策。

Schema 3 必須明確啟用。現有 Schema 1／2 catalog 仍依相容規則讀取；已核准或執行中的舊工作不能默默升級為 Assistive 狀態模型。先釐清責任歸屬，再建立新的搬移流程。

目標主機操作人員

  1. 在指定目標主機盤點並保護快照實際 bytes。首次觀測的目標快照只是基準標籤，不能證明主機原本空白或乾淨。
  2. 審閱目前差異與必要軟體。若選定軟體尚未準備好，選擇 WaitForInstall；項目會延後處理，且不得寫入目標。
  3. 準備完成後，建立綁定 Pair、sealed plan、manifest、世代、目標快照、比較 revision、選取 revision 及選取子集的 target decision receipt。子集只能等於或小於已核准 Include 集合。
  4. 寫入前再次預覽衝突與工作負載準備情況。目標端既有且不屬於本工具的物件或檔案視為衝突，不會默默取代。
  5. 透過受支援流程執行還原。持久狀態與 journal 應由目標操作人員連同受保護證據保存。中斷後重新連回同一作業；不要另開世代當作快速復原。
  6. 逐項檢查狀態與讀回。延後、阻擋、衝突、人工處置、需重新啟動、失敗及取消的工作都必須保留原狀態。

軟體與版本選擇

Windows 版本由目標作業系統決定。其他產品的來源版本只供參考；操作者可選不同目標版本並依組織核准流程安裝。catalog 必須分開保存 source version（來源版本）、chosen version（選用版本） 與 observed target version（目標觀測版本）。

版本相同或較新不等於相容

版本相同或較新，不足以證明 provider、架構、帳號範圍、授權、runtime、設定、檔案格式或應用程式行為相容。不要自動改寫資料格式或轉換設定；由產品及應用程式負責人驗證支援的升級路徑。

缺少產品時，記錄安裝負責人、選定版本、安裝媒體／來源、授權、設定前置條件及驗證方式。唯讀環境探測只回報觀測；探測通過不代表資格認定、還原、安全或業務測試通過。

人工工作應列明責任人、程序、所需證據及下一步。安裝後若比較改變，先重新盤點目標並發布新比較，再使用結果。

變更目標路徑不會改變來源項目身分。路徑映射必須出現在實際使用該路徑的 IIS 或排程欄位，不能只記錄在檔案複製結果。列出原始值、審閱後目標值、欄位指標及處置方式。不透明排程參數、指令碼及未解析設定仍由人工處理；不要全域取代字串。

逐檔選取受核准檔案白名單限制。即使目標應用程式改用新位置或格式，也要保留原始路徑與 bytes。檔案已複製不代表目標應用程式確實使用它。

IIS 與排程工作負載

審閱網站、application、virtual directory、pool 或排程時，檢查所有影響所選工作負載的發現參照，列出共享資源已選、未選與未知使用端。共享 pool、排程資料夾權限或全域／分節設定可能影響畫面項目以外的工作負載。

  • IIS 與排程物件以停用狀態 staged。型別化啟用決策與寫入、讀回分開處理。
  • 分別審閱來源 XML、映射後目標值及啟用意圖。原始來源 XML 留在受保護證據中；HTML 僅呈現安全的型別化投影。
  • IIS 全域與指定 location 的分節變更只能套用到已審閱分節及型別化欄位。遇到不支援節點語意或無法確認集合身分時，必須人工處理。
  • 排程 actions、工作目錄、principal、觸發條件、設定與資料夾安全性必須整體審閱。不透明 arguments 不可自動改寫。
  • 工作負載所需的非 C 磁碟區檔案仍屬工作負載範圍，透過獨立 D 通道結果處理，不會併入 C 封包項目。

所有可取得的非 IIS 發現項目仍須明確處置。本流程不會為不支援產品新增專用 adapter。

衝突、延後處理與部分結果

目的端既有內容預設保留。報告應指出受影響項目及衝突類型：檔名碰撞、檔案／目錄路徑互相佔用、未擁有的原生物件、未解析的使用端映射或較大範圍阻擋。不要要求操作者清空 Windows 或產品共用目錄來排除衝突。

DeferredSoftware安裝或準備相依項目，重新盤點、比較並再次決定。
WaitForInstall責任人明確選擇等待；這不代表還原成功。
BlockedConflict目標物件或路徑已存在，且沒有精確擁有權證明。
ManualEvidenceRequired仍待指定責任人完成程序或提供已接受證據。
Failed / Cancelled重試前保留操作 journal 並查看復原指引。
Partial部分獨立項目可能已準備完成，其他項目仍被阻擋或延後。

除非明列分母及所有未完成已選工作，否則不要把綠色項目數換算成整體成功百分比。C 與 D 結果、原生物件寫入、人工準備、業務驗證及切換各有獨立狀態。

可攜式 HTML 報告與證據套件

匯出會建立離線 index.html 與 evidence/ 資料夾。使用支援瀏覽器在本機開啟；整個套件一起搬移時，相對連結仍應可用。evidence 資料夾包含以 hash 綁定的中繼資料參照。原始盤點、設定與 XML 留在受保護工作區，不會複製到可攜頁面。

報告索引不可變來源快照、可取得的目標基準／目前快照、軟體觀測、選取與決策、比較、搬移路徑與人工工作、匯入結果參照及目標決策歷程。每項結果都會說明可證明與不可證明事項。缺少證據時保留 NotTested、未知或未記錄狀態。

HTML 投影不包含原始 XML、完整設定、排程 arguments 或秘密。另行保存受保護工作區；可攜 evidence 資料夾只有參照，不能取代原始盤點或設定。Hash 可偵測 bytes 是否改變，但不能單獨驗證製作者身分。

Manager 報告不是目標 journal，也不會重建 journal。工作台報告連結先核對受控參照及 hash，再將檔案交給 Windows 預設程式；`Opened` 只表示已交付給 Windows 開啟，不代表報告已顯示。報告本身不會核准計畫、證明目標讀回、接受業務行為、完成 C／D 傳輸、授權切換或釋放來源主機。

驗證、切換與來源退役

還原後由目標操作人員核對指定世代的狀態與實際讀回。業務負責人測試身分、存取、整合、排程、監控、備份與復原等真實行為，記錄責任人、證據、時間與世代。

還原後由目標操作人員驗證指定世代狀態與讀回。應用程式負責人檢查身分、存取、整合、排程、記錄、監控、備份與復原等實際行為，並記錄實際受測的負責人、證據參照、時間及世代。

Cutover 有獨立準備與執行紀錄。協議觀察期間內保留來源主機。切換後業務與營運接受完成後，才另行決定來源退役。檔案 hash、原生 API 讀回、安裝程式觀測或報告匯出通過，都不能取代該接受程序。

Production qualification（正式環境資格）評估工具與支援環境，和單次隔離搬移分開。外部前置條件及具代表性的主機／資料證據尚未被接受前，資格狀態應標為 NotTested 或「尚未建立」。

來源磁碟與最終還原核對

主包與非 C 通道以來源實體磁碟分流。若 SUBST 或掛載路徑的盤符分類與實體 C 身分不一致，工具拒絕封裝／搬移；請改以原始磁碟路徑重新審閱，不把別名當成另一磁碟。目標位置仍依核准映射處理。

還原檔案後套用父目錄設定可能改變繼承 ACL，因此工具在全部目錄設定完成後再次核對檔案 bytes 與必要 metadata。未通過最終讀回的項目列為失敗，保留 journal 與原材料，不用新的觀測值直接認領漂移。回退也在所有父目錄設定還原後重查 prior 檔案與目錄；若最終 bytes／metadata 不符，保留復原意圖，不能回報已回退完成。

非 C 的實體位置與 SMB peer 證明沿用盤點／註冊主機的同一身分指紋。升級工具後，請重新產生舊版位置證明並核對當輪來源／目標，不手動修改 proof JSON。搬完子檔後，工具只對本次建立且 journal 證明持有的目錄恢復來源時間戳，再完整讀回 owner、DACL、屬性、時間與存取；外部既有目錄保持衝突／人工處置。

非 C 結果匯入屬觀測證據；同一有效 sealed plan 的核准與決策版本保留，後續目標 receipt 及還原／切換階段結果仍可接續。若來源選取、規格或核准計畫已改變，舊結果會被拒絕，必須重新檢查當輪材料。

審閱不同項目的草稿

同一頁的操作選單之間切換會保留目前記憶體草稿；重新載入頁面後草稿即失去。sessionStorage 僅保存非秘密的作業追蹤 metadata，不保存表單草稿、token 或秘密。明確按某項目的「帶入審閱表單」時，表單改用該項的審閱內容，先前項目的欄位及進階 XML 引用會被取代；請先保存需要保留的審閱。預填仍須逐項確認負責人、佐證、revision及預覽，再提交與重新核准。

檔案權限還原政策

在檔案範圍的「規格審閱 → 保存規格審閱」表單選擇 AclControlPolicy；預設 Exact，要求必要 ACL 精確一致。只有經負責人審查、取得組織同意後，才可選 AllowAutoInheritedUpgrade，容許 Windows 套用 ACL 時新增 AI（自動繼承）控制旗標。這不容許 owner、group、任何 ACE 或 P／AR 旗標漂移，也不會自動修改原有核准。

變更政策後提供負責人與佐證，重新預覽、保存規格並重新核准當輪計畫；已封存或執行中的材料保持原契約，不能在還原失敗後直接改 JSON 放行。工具仍會在父目錄設定完成後核對全部檔案與目錄。

疑難排解與安全的下一步

遇到比較過期、證據 hash 不符、路徑未解析或工作中斷時，保留原始材料並先核對權威工作紀錄；不要修改受保護 JSON 來繞過檢查。

報告顯示目標基準是首次觀測

這是刻意保留的狀態。重新取得並檢查目標目前盤點；沒有獨立證據前，不要稱它為乾淨基準。

比較後軟體版本或設定已變更

取得可信目標目前事實後再更新。重新發布比較；綁定 hash 或 revision 已改變的決策收據必須重新建立。

報告連結失效或證據 hash 驗證失敗

保留套件原樣，確認整個資料夾完整搬移，再從受保護工作區重新取得參照證據。不要編輯 JSON 來讓 hash 驗證通過。

路徑或排程參數尚未解析

指定負責人檢查實際使用端並選擇安全目標值。型別化映射經審閱並出現在使用端設定前，項目應維持人工處理。

工作已中斷

沿用相同 state directory、封包、journal 與世代。修復或重試前檢查持久作業紀錄與復原預覽；保留意圖不明紀錄及備份。

檔案報告通過，但工作負載仍無法使用

檔案放置只是其中一個關卡。另行檢查工作負載設定、軟體、身分、網路、相依、執行行為與業務接受。

本手冊提供操作參考；請遵守環境核准的變更、安全、證據保存與復原程序。 即時 catalog、sealed plan、target receipt 與 target journal 分別是各自狀態的權威紀錄。
