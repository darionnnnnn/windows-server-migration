目前能做什麼

第五輪已提供易讀的用途選擇、精靈步驟與保存的項目選擇。真 Edge 連接正式本機 PowerShell handler，已驗證空工作用途選擇、步驟版本檢查，以及使用隔離盤點資料進行分組選取、保存、返回和排除理由。

完整備份與還原仍在實作

真實備份封裝、C 槽及非 C 槽成果核驗、交接後的新主機還原旅程（E／F）尚未完成驗收。盤點或選取已保存，不表示備份已建立。使用前先查看目前實作狀態與待驗項目。

第四輪在特定 AdGuard 環境記錄的原始傳輸完整性仍是 NotPassed；第五輪有限的正式 handler／Edge 操作證據不代表該傳輸差異已解決，也不代表完整備份或還原旅程通過。隔離測試、fixture 及 mock 結果只證明其明列範圍。

啟動與選擇用途

  1. 開啟工具在工具資料夾雙擊 Start-ServerMigration.cmd。保持啟動視窗開啟，工作台會在本機瀏覽器顯示。
  2. 開始或繼續按「開始／繼續操作」。第一次使用時，選這台電腦的用途：舊主機、新主機，或整理搬移資料的電腦。已登記用途會恢復。
  3. 照畫面前進按「下一步」完成當前步驟。若要修正選擇，可返回前一步；已保存狀態會按工作及版本檢查。

用途只是流程上下文，不是 Windows 登入身分、系統管理員權限、工作核准或目標主機授權。工具不會替你繞過執行政策；如啟動受政策封鎖，請管理員按組織程序核准。若沒有瀏覽器，資訊人員可使用共用 PowerShell 核心的文字選單。

舊主機：掃描與整理項目

舊主機負責在本機收集可支援的網站、排程、服務、軟體設定及資料檔案。精靈會按業務項目分組，而不是逐檔詢問；需要確認細節時才展開檔案範圍。未支援、權限不足或不完整的內容應保留為缺口。

  • 已發現且有可信掃描結果的項目可以逐組選擇或排除；排除理由會保存在當前工作決策。
  • 精靈中顯示的選擇是搬移意願，不能代替 sealed plan 或有效核准。
  • 自動模式僅代表依本次選擇自動加入可支援項目，不提供不存在的目標身分、owner 證據或管理核准。
  • 真實封裝及非 C 通道成果尚未完成第五輪驗收。不要把掃描 ZIP、盤點結果或選取摘要稱為已備份資料。

自動備份必須沿用現有搬移核心：來源、目標及核准計畫相互綁定。開始備份前需要真實新主機身分及符合當前材料的核准；沒有這些條件時應先整理掃描結果並完成管理準備。

整理搬移資料的電腦：核對交接材料

管理端在自己的工作區整理來源材料、目標觀測及比較結果。它不是遠端控制台，不會代替新主機上的操作者。舊主機交來的材料必須核對可信來源及獨立 SHA-256；材料內自帶的雜湊不能單獨證明製作者或批准者身分。

  • 以已登記的工作與主機識別綁定材料；不要只靠檔名、時間或文字標籤判定對應關係。
  • 目標觀測、比較與計畫必須對應同一組來源／目標身分、目前世代及核准範圍。
  • 責任人欄位是責任聲明，不會驗證填寫者身分；缺少外部可信證據時應顯示待確認。
  • 管理端整理選項不會授權還原、啟用服務、切換或來源退役。

第五輪目前沒有完成真實備份交付到新主機還原的完整導引。需使用進階核心時，資訊人員應按[操作契約](OPERATIONS.md)及組織程序逐步處理，並依[復原指引](RECOVERY-RUNBOOK.md)保存 journal、封包、收據及讀回證據。

新主機：還原、驗證與啟用

新主機須在自己的本機工作區取得可信目標身分及目前狀態。還原流程應重查來源封包、目標快照、比較 revision、選取範圍與核准，再顯示可還原、衝突及待準備內容。

還原需要單獨確認

自動備份選項、管理端用途及一般「下一步」都不授予 Restore 權限。還原操作需明確確認，核心會再次檢查已核准材料與目標狀態。

啟用另有一道 gate

還原完成不表示服務可用。IIS／排程／服務等維持受控 staging；業務驗證及正式啟用須有獨立決策與所需證據。生產執行目前停用。

目的端既有檔案或物件不會默默覆寫。相依軟體未準備、目標衝突、材料過期或範圍超出核准時，應保留阻擋並依提示處理。等待補裝、部分完成、失敗及取消都不能顯示成全部完成。

材料信任、目標綁定與外部證據

現有封裝依賴核准的 sealed migration plan；核准內容會綁定真實 TargetIdentity、工作範圍及工具 bytes。精靈可替你從有效材料帶入路徑、hash、revision 和已觀測版本，但不能從不可信檔案自行判定獨立可信 hash、責任人或組織批准。

獨立 hash 可確認 bytes 是否改變，不單獨證明誰製作或批准材料。目標身份、owner 證據、業務接受、企業簽章及正式變更批准仍需各自可信來源。工具主機用途不改變核心授權。生產資格保持 ProductionVerified=false，生產執行保持關閉，發行包目前未企業簽署。

開發者環境探測：獨立的一鍵唯讀收集

左側「開發者環境探測」供後續開發蒐集本機資訊；沒有配對或盤點結果也可使用。按一次會排程已登錄且適用的唯讀收集器，個別失敗會以狀態及原因保留。

  • 探測 ZIP 含匿名化的 probe.json、繁體中文 HTML 摘要、索引及檔案雜湊。格式版本為 1.0。
  • 原生盤點等原始材料只留在工作區內受保護的本機探測資料夾；可交付 ZIP 只含整理過的摘要。
  • 欄位遮蔽涵蓋憑證、私鑰、wallet、XML／指令碼、命令列、帳號、主機名稱、絕對路徑及錯誤／標頭中的敏感值。
  • 輸出固定於工作區的 developer-probes。工具不自動上傳，不將資料加入 Git；交付前仍應依組織規則檢查目的地及內容。
  • 權限不足、空間不足、逾時、截斷及不適用會明列，不會被當作成功。UNC 與 reparse-point 遞迴不在探測範圍。

若工作台無法使用，資訊人員可在本機工具目錄執行同一收集器：

powershell.exe -NoProfile -File .\Start-ServerMigration.ps1 -Action DeveloperProbe

此備援使用預設工作區的同一收集器，不要求另外手填路徑或角色。DeveloperProbe 只描述觀測，不改寫權威搬移計畫、不做還原／啟用，也不代表 Server 資格或業務驗證已通過。

支援範圍與排除項目

支援方向工具已實作的網站、Windows 排程、服務、軟體設定與資料檔案。
非 C 槽資料遵循既有核准、來源／目標身分及跳板通道；不複製成任意磁碟備份。
不包含整機映像、作業系統、System State、軟體本體及未實作的產品專用 adapter。

Oracle、資料庫及其他專業產品的軟體本體、授權和產品特有程序由負責人依產品文件處理；工具可列出已支援的設定或差異，但不因此宣稱支援完整產品還原。實際 Server 2016／2025、IIS、排程、帳號、PKI、規模與業務驗收仍需代表性企業證據。

中斷、取消與續作

  • 關閉瀏覽器不一定會取消正在執行的工作；結束啟動視窗可能中斷本機程序。以工作識別查詢權威狀態，再決定下一步。
  • 寫入提交逾時或斷線時，先查原 operationId 的結果，不要盲目建立新操作重送。
  • 取消要求不等於工作已停止。確認 worker 與作業狀態後，再使用相同工作、世代及受控材料續作。
  • 保留操作 state、append-only journal、封包、收據、hash 與目標讀回。不要手改 JSON、刪除鎖或丟棄不明紀錄。
  • 若工具回報雜湊、主機身分、核准或目標狀態不符，停止寫入並交由指定 owner 核對。參閱[復原 runbook](RECOVERY-RUNBOOK.md)。
