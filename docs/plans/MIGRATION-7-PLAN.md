## 1. 本輪目標與範圍定案

1. **套裝軟體不備份，但另行安裝的軟體必須完整列入評估清單。** 包含與 IIS／排程無直接相依的已發現軟體；由使用者決定新機是否安裝與選用版本。來源事實、使用者意圖、目標觀測三者分存。
2. **搬移 C 槽的適用資料，加上 IIS／工作排程器使用的目錄，不受來源磁碟位置限制，還原到相同位置。** C 槽解讀為既有範圍內的業務檔案、設定及資料；延續不做整機映像、Windows／System State／產品安裝本體備份。這不是只搬 C 槽中的 IIS／排程目錄，也不是無條件遞迴複製整個 C 槽。
3. **盡可能減少 EOS 移機操作負擔。** 工具推導候選範圍、原位置、相依及待辦；使用者集中確認意圖、歧義、責任及必要授權。工具不能推導的部分明示缺口，不靠重複輸入或假成功隱藏。
4. **C 槽由工具主動探索候選，再由使用者確認。C／非 C 所選資料都必須有獨立離線備份。** 舊機關閉後，新機只使用已驗證備份集、工具及必要的新機憑證即可還原，不回頭讀舊來源或舊機工作區。
5. **準備完成後一鍵執行。** 舊機按一次「開始備份」，完成後以 HTML 看全部已發現項目及各項結果；新機在 HTML 勾選要還原的項目，確認預覽後按一次「開始還原」。需要帳號密碼時由 HTML 對話視窗收集並續作；一鍵不代表省略必要準備、改變範圍核准或自動啟用業務。

### 邊界與既有政策調整

- 已安裝套裝軟體、runtime、Oracle Client、IIS 安裝本體皆不進 payload；網站自有 DLL／EXE、業務腳本仍可搬。套裝軟體內必要設定僅依既有精確設定檔契約保存，不擴成整個安裝目錄。Portable 類別不得成為搬套裝本體的繞道；自有可攜業務程式與第三方產品分辨不明時要求確認。
- 非 C 的一般無關資料不自動納入；IIS／排程使用的本機目錄、明確輸入輸出及其必要相依須列出。不因安裝目錄被排除，就隱藏該產品的補裝需求與設定保存方式。
- 新建本輪流程採原位置還原，取代正常流程自由改目的地的策略。缺磁碟、路徑被占用或權限不足時列待辦，不偷偷改到其他磁碟。既有執行中的核准映射、receipt、journal 以原可信工具完成／回退，不原地改寫。
- 「不管在哪裡」包含 UNC、環境變數、相對路徑、掛載點及無法解析的引用之盤點與處置；不等於已支援全部儲存型態。UNC 需區分沿用既有外部共享與另行遷移共享；未取得可信主機／路徑／範圍證據不自動複製。映射磁碟不得用管理者的登入環境冒充排程帳號環境。
- 使用者本次明確取代「C 主封包／非 C 僅直接傳輸」限制：新增 C／非 C 統一離線備份集與新版本材料契約，沿用可重用的分卷、hash、journal、檔案防護及同一執行核心，不新增遠端常駐服務。舊 NonC 直接傳輸僅供既有工作接續，不能代替本輪離線交付。
- 備份仍依既有目標綁定核准；「舊機可離線」不等於取消目標身分或新增無目標 SourceOnly 格式。首次 Target 登記／Manager 審閱由精靈引導，完成後才一鍵備份；新機可在已封存核准集合內選還原子集，不需讓舊機重新上線批准每次勾選。
- 原位置保存與新版軟體能否使用分開判定；不自動轉格式、改任意腳本／Arguments 或宣稱版本相容。原檔保存成功不等於設定已生效。

### C1：全機已發現軟體評估表
- 所有可觀測另行安裝軟體均出列，不限已選工作負載；涵蓋機器／使用者 scope、32／64 位、未載入 profile 缺口、可攜與人工補登。不能讀取或搜尋預算耗盡時列原因及補查方式，不回報「全部找齊」。
- 每列顯示名稱、已知版本／架構／位置／來源證據、相依工作負載、目標觀測、是否另行安裝的決策及必要人工待辦；未知版號不刪名稱。名稱相同但版本／帳號 scope 不同不得誤合併。
- 新機 Windows 初始基準用以比較，不將 OS 內建項混稱使用者安裝；身分不明保持未知。
- 驗收：無關軟體仍可見、未知版本、雙架構、多帳號、權限不足及空盤點皆有反例；列表／匯出／目標比較數量與同一來源集合一致。

### C2：排除與使用者決策接到正式使用端
- 套裝本體在候選、核准、C／非 C 離線封存與還原全程排除；安裝在自訂 C/D 路徑也適用。不得單憑副檔名排除業務 DLL／EXE。
- 安裝評估支援保留／批次確認使用者意圖，不能代填未知產品、秘密或批准。僅已選工作負載的必要產品未準備才阻擋相依操作；無關軟體不阻擋純檔案。
- 驗收：套裝本體不出現在兩通道 payload；已核准業務二進位及精確設定檔可讀回；Portable／父目錄／別名不得繞過防護；缺可信安裝根時不可假稱排除完整。

## 7. 作業 D：備份範圍及跨位置相依

### D1：範圍候選與覆蓋缺口
- 分列 C 槽可搬資料、IIS 物件／設定與目錄、排程定義與全部 action 引用。C 槽主動有界探索，包含未與 workload 關聯的候選與根目錄散檔；讓使用者確認而非只提供手動加入。逐區域顯示覆蓋與缺口，不以找到工作負載就宣稱全盤資料已涵蓋，詳第 15.2 節。
- IIS application／virtual directory／configSource，以及 task Command／WorkingDirectory／可明確解析的輸入輸出／腳本引用，保留來源與 consumer 關聯。不可解析參數及動態腳本相依列「需確認」，允許使用者補登精確檔案／資料根，不執行腳本來探測。
- 環境變數與相對路徑以可信來源及實際執行帳號 context 解析，不以 Manager 環境展開。共享相依去重但保留所有 consumer；巢狀與同名不同位置不得誤合併。
- 驗收：C/D/E、UNC、環境變數、相對路徑、多 action、資料檔參數、缺 WorkingDirectory、未知 action、循環及共享目錄案例；未解析相依明列，不能因集合為零回報 100%。

### D2：候選到核准範圍的閉合
- 工具提出候選與排除理由，使用者一次確認業務資料根；程式檔候選不得無條件擴為整個安裝父目錄。C 無關資料與非 C workload 必要資料按不同納入理由追蹤。
- 同一備份工作整合 C／非 C 的範圍、容量與離線結果；來源本機非 C 封存不要求虛構目標 SMB peer proof。只有實際經 UNC 讀取時才需對應來源遠端證據；新離線目標不依賴舊直傳結果，改以備份集及本機還原證據核對。核准、停寫與主機綁定仍有效。
- 不支援長路徑／reparse／特殊檔案等沿既有政策明列阻擋與處置；不因「任何位置」偷偷放寬。
- 驗收：正式 candidate→review→sealed plan→C／非 C payload→逐檔 hash；只有 NonC、只有設定及混合部分失敗均準確呈現；人工排除必要相依不能顯示工作負載完整。

## 8. 作業 E：相同位置還原

### E1：原位置契約貫穿全鏈
- 新流程以來源絕對邏輯位置建立預期目的位置；C:\Jobs 回 C:\Jobs、D:\Sites 回 D:\Sites。規範大小寫／分隔符等等價形式，不以字串形式掩蓋實體 root／共享／掛載差異。
- 原位置承諾由 spec／plan／receipt／preview 到 writer 驗證；正常流程不能用 UI、CLI 或匯入材料繞過而改寫其他目的地。原始 bytes 與來源引用保留。
- 既有映射 helper 的其他使用者先全面核對；不為本流程直接刪除共用能力，不提供吞掉新限制的相容入口。新增資料若需要版本欄位須明列升級策略，執行中舊 state 不轉版。
- 驗收：C 與非 C 真檔案同位置讀回、篡改目的地被拒；來源與目標本來就是不同主機／磁碟，不要求兩端 volume ID 相同。應拒絕的是目標相對其已核准實體根的漂移／替換，不是正常新機。舊已核准工作以原工具接續，不因新規則靜默改位置。

### E2：目標缺口、衝突與續作
- 執行前確認磁碟／掛載／容量／權限及目的衝突。缺 D 槽列「準備相同位置後重查」，不改到 C。UNC 沿用／遷移責任與證據明列，不能把遠端位置自動改成本機。
- 不覆寫／合併外部既有檔案；既有受控 delta、ownership、journal replay 繼續依原契約。缺軟體的獨立資料可先保存，相依設定 deferred，待補裝後續作。
- 驗收：缺磁碟、權限不足、同名檔、合法受控 delta、部分取消、crash／重播；完成內容不重做，缺口未解不報全部成功。IIS／task 保持停用，啟用仍另經確認。

1. **原位置只約束工作負載資料的目的位置。** 非 C 的來源／目的 UNC 搬運共享可不同，但其 proof 必須指向各自主機已核准本機根；不得要求把目標共享命名成來源主機，也不得向舊來源 UNC 寫回。外部共享本身的保留名稱／DNS／主機切換仍是原有外部協調責任。
2. **預設、排除與自動模式一致。** 已發現支援項沿用既有逐項／明確自動加入模式；既有排除保留，新發現相依需審閱。一次確認只套明確集合，不自動批准陌生帳號／未識別軟體。未選必要相依及共享 consumer 影響不得只留在進階頁。
3. **成功口徑可核算。** 逐通道檔案／位元組進度與逐工作負載完成分開。去重檔案只計一次，所有 consumer 都要有結果；已排除、外部處理、未探索、失敗與未驗分列。分母為零顯示不適用或無可執行項，不回報「全部備份成功」。
4. **批次並非全機同生共死。** 某軟體未知／NonC 不通只阻擋確定相依的集合；若無法判定關聯，說明不確定範圍，不擴成無理由全域阻擋，也不忽略必要相依。部分完成必須可接手並續作。
5. **CI 測的是實際產品與交付物。** 變更選擇須涵蓋產品 consumer 及測試 runner 相依；required check 不因 path skip 永久 pending，聚合結果不得把應測但未跑視為成功。適用的 release journey 必須記來源 commit、解壓工具指紋及實際執行引擎；文件-only 免產品回歸仍需檢查本地引用與發行文件差異。
6. **A 索引不另造龐大維護系統。** 利用既有證據記錄產生／核對精簡表；永久證據不能只引用會到期的 runner artifact，也不能把含真實盤點的 log 推進公開 repo。缺失或不可取得的舊證據明列，不能補造 PASS。

### 14.4 從頭到尾的全專案檢查與執行調整

完整資料鏈重新核對為：來源觀測與可信 context → 軟體／資料分類 → 候選覆蓋與缺口 → 使用者意圖及全部 consumer → 目標身分／原位置能力 → Manager sealed 核准 → 同窗口 C／NonC 取得材料 → 可信交付／receipt → 目標預覽與明確還原 → bytes／metadata／設定 readback → 補裝後重查 → 獨立啟用與業務接受 → 觀察／回復／退役。每段輸出都要由下一段正式使用端消費，不能只加報告欄位。

第二次複查當時加入 E0；目前完整順序已更新於第 3 節，包含 D3/E3/F3/F4。E0 可獨立窄修，但不在本次執行；C、D、E 的資料版本與範圍規則先對齊再提交，不能先由 UI 發出核心不接受的新契約。

G 新增下列機器可判定的整合劇本，覆蓋分母／結果並檢查實際檔案，不以按鈕存在作驗收：

- 未關聯 C 資料＋混合套裝／業務檔＋跨磁碟 IIS／多 action 排程；含父子 scope、共享 consumer 及相同名稱不同路徑。
- 空 Target 正式交接起步，缺 D 槽先 deferred、補齊後重查／續作；合法不同主機實體根通過，核准後目標拓撲改變拒絕。
- C 完成／NonC 失敗／來源離線及共同 freeze 失效；結果不誤報完整備份、不觸發退役或啟用。
- 安裝新版改寫已還原設定、同名不同 SID、目標權限變更；已完成歷史保留而目前結果重新判定。
- 未解析參數、來源與 Manager 變數差異、秘密投影、重開接手／雙頁及零可執行項。

第二次複查結論：初版存在 E0 草稿缺陷及多個跨段驗收缺口。當時兩項待決已於後續使用者答覆定案，見下節與第 15 節。沒有進行全面產品測試或不同模型收尾簽核，也沒有解除第六輪及外部資格限制。

## 15. 第三次定案：完整離線備份與 HTML 一鍵還原

### 15.1 使用者實際操作與一鍵的界線

| 步驟 | 使用者看到／操作 | 工具責任與完成判準 |
|---|---|---|
| 1 舊機盤點 | 開啟 HTML，執行探索，查看軟體與 C／IIS／排程資料候選。 | 顯示探索進度、已探索／未探索區域、候選理由及排除；不自動把候選當核准。 |
| 2 準備與確認 | 確認備份集合、目的媒體與停寫影響；首次依引導完成目標身分及 Manager 審閱。 | 收齊可推導資料，阻擋項附可操作下一步；無需手填內部 hash。備份範圍與還原選取分離，備份保留使用者已確認集合。 |
| 3 一鍵備份 | 按一次「開始備份」，看進度／取消／結果。 | 同一耐久作業編排 C／非 C 與設定封存、分卷及驗證；不能要求使用者逐磁碟另跑工具。缺權限／未知相依明列，不能靜默跳過。 |
| 4 備份後清單 | 從交付資料夾開 HTML 查看所有已發現項目、範圍、軟體與缺口。 | 靜態離線閱讀不連舊機；每項標已備份／未選／排除／外部處理／失敗／未驗，不把「有清單」當「有 payload」。 |
| 5 新機接收與勾選 | 新機啟動本機工具、匯入備份集；在 HTML 勾選要還原的網站、排程及資料範圍。 | 驗材料／主機／版本／必要卷，核對原位置及軟體缺口；自動計算必要相依並顯示勾選影響；無備份的套裝本體不能勾成可還原。 |
| 6 一鍵還原 | 確認最終預覽，按一次「開始還原」；需要時在 HTML 對話視窗輸入帳密。 | 建立所選子集的耐久 attempt，自動依相依順序執行；缺秘密時等待而非直接失敗或卡在背景 Read-Host。 |
| 7 結果與續作 | 查看成功、待補裝、待帳密、衝突及失敗，補齊後按續作。 | 已成功不重做、未知提交只查同 ID；續作重查必要條件。還原完成不自動啟用網站／排程，也不代表業務接受或可退役。 |

「一鍵」指上述準備完成後的一次明確啟動及整體編排，不強迫使用者反覆提交每個內部階段。若 scope／target／核准變更，需新的預覽與明確確認；輸入原已核准帳號的密碼則是續作資料，不重造另一份搬移授權。仍需其他機器、企業網域或外部產品條件的操作會出列，不能把離線還原誇大成完全不需任何外部依賴。

### 15.2 D1/D2 補強：主動探索與安全範圍

- 有界探索覆蓋 C 根目錄項目與可讀子目錄，優先呈現 workload 已知引用及一般資料候選，保留使用者可見的續查範圍。受保護區域只列排除／待處置原因，不遞迴擷取 OS 或產品本體；權限不足、掃描取消、預算截止各自記錄位置與原因。預算數值暫定，依試驗配置但不得將未探索區域藏掉。
- 探索只產生 metadata／候選，不自動執行檔案、不自動載入未知程式、不無限追 reparse。來源變動會使相應候選與核准需重查；反覆探索依穩定來源身分合併，不把全部舊排除清掉。
- 根目錄一般散檔需新增可封存的「精確一般檔案集合」行為契約，與設定專用 ExactFiles 分開；只有已確認的完整檔名可選，不能形成 C:\ WholeScope。每個成員獨立套用系統／安裝本體、實體路徑、特殊語意與輸出重疊防護，未知成員不授權，新增鄰居檔不自動納入。
- 父子資料根合併須先證明排除、metadata 政策、相依及核准一致；否則保持兩範圍並解決歧義，不以「取最長路徑」偷偷改授權。一般精確檔集合要同步支援候選、spec、sealed plan、payload、receipt、restore、delta 與報告；版本不相容時拒絕，不能降成整目錄。
- 驗收：C 根散檔、零長檔、空資料夾、中文／空白路徑、不可讀子樹、混合套裝目錄、掃描取消後續查、根新增鄰居檔、父子／共享範圍，逐一追到封包及原位置讀回。

### 15.3 D3a：離線備份集材料與相容契約

**目標：單一可攜交付集合，包含全部已確認可備份 C／非 C 檔案及必要控制材料。** 可以有多卷／多檔，不要求巨大單一 ZIP；沿用 Directory／分卷 ZIP 選項與已驗限制，格式在 attempt 建立時固定。

- manifest 表達備份集身分、來源主機、核准計畫、世代／attempt、每個來源根與原位置、項目／檔案關聯、metadata、檔案大小／雜湊、全部必要卷與控制材料。欄位名稱及版本號實作前定案；語意不能只靠檔名推論。C:\Data 和 D:\Data 不得在封包內碰撞。
- 使用安全內部成員路徑或內容雜湊存放 bytes；來源絕對位置只作受驗證 metadata。解包不得直接把 manifest 路徑當目的地，禁止 traversal、絕對 member name、重複衝突索引及未支援 stream／連結繞路。新機寫入仍需原位置預覽及核准。
- 備份集包含所需 inventory／軟體清單、原始設定／受保護證據、核准範圍、相依索引、檔案及必要 metadata、可驗來源擷取結果與離線報告；不能只有舊機 WorkRoot 的絕對引用。原始應用機密設定沿既有保護處理，不能把它們輸出到公開清單。
- 不能依賴舊機專屬的 DPAPI／機器私密狀態才能讀取新機必需材料；若現有材料有這類綁定，設計可攜的受控保護／重新輸入路徑並作新機測試。操作帳密不放備份；不可攜的加密應用秘密／私鑰仍列外部處置，未完成不能聲稱該 workload 完整可用。
- 沿用既有可信核准／獨立可信來源驗證；包內自己帶的 hash 只能核完整性，不能自我授權。報告 HTML／索引／實際 payload 綁同一備份身分，不能拿另一包的清單來還原。
- 新能力需顯式版本／feature 支援判定：舊 reader 不可忽略 NonC 或一般精確檔集合後回報成功；新 reader 對舊 C-only 包如實顯示限制。舊材料不得靠補一個旗標升格成離線全量備份；舊工作沿原版本接續。
- 正式能力盤點已確認 `AssistiveFiles.ps1` 的 Test-WsmAssistivePackageScope 只接受 proof.Channel=C，Payload 又以此決定封裝成員；SourcePolicy 目前僅接受 SourceCOnly。需同步 source policy、collection proof、manifest validator 與所有 reader，不能只在 WizardBackup 多加 D 槽迴圈。
- 第一版離線交付為自足 full 集合，不依賴未隨附 base 或散落別處的 delta。既有 delta／Fleet／LabReport consumer 要辨識新能力；尚未支援的入口明確拒絕，不消耗新格式作部分成功。後續增量若使用，必須帶齊可驗 base 鏈，不在本輪偷增新的增量模式。
- 驗收：多磁碟同名相對路徑、混卷／少卷／重複卷、控制材料缺失、內容竄改、路徑逃逸、未知版本、舊包限制、被刪 base；writer／reader 對同一集合完整核對，不能只通過 JSON schema。

### 15.4 D3b：實際封存與獨立可恢復判準

- 來源本機 C／D／E 使用同一受控檔案擷取核心；不得直接刪掉舊 C-only 判斷就放行所有路徑。新的來源根白名單、可信來源身分、套裝排除、精確集合與已核准 scope 一起驗證。UNC 是另一種來源觀測，只有明確納入且受驗的內容才能封存，外部服務不能用空 placeholder 代替。
- 同一使用者動作產生一個耐久父作業，子階段結果可追查但不能各自宣布整份備份成功。需要停寫的已選 writer 及 C／NonC 共用一致性契約；封存期間來源漂移、失敗、取消後保留部分結果，不自動變更已確認範圍。
- full 集合 finalization 前驗所有必要成員 bytes／metadata／控制材料，再發布完整索引。不能先把清單標完成再慢慢補 NonC。零資料但有設定的有效集合可完成；零有效工作顯示無可備份內容。
- 區分「已在來源完成封存」與「已驗證獨立副本」。只存舊機本機磁碟不滿足關機後可取用；精靈引導輸出／複製到新機可存取的獨立媒體並核驗全部必要材料，之後才顯示離線還原材料已就緒。網路媒體是否可取用不從 UNC 名稱猜測，工具無法觀測時保留待確認。
- 容量涵蓋來源暫存、最終分卷、交付副本、新機 staging、原位置寫入與必要回復；來源／輸出／暫存及本機既有備份相交需驗受控排除。存滿、拔除媒體、取消及 crash 不可破壞先前有效備份，重試不得混入另一世代。
- 備份的擷取時間與當時 freeze 證據保留；舊機離線後不要求重新取得來源 live proof 才能還原。不可把來源「目前仍停寫」作為日後讀備份的前提。切換／避免雙 writer 的最新證據仍在獨立啟用階段處理，備份成功不授權退役。
- 區分擷取當時有效的不可變來源證據與執行時需要新鮮度的目標授權／觀測；既有時效檢查逐一分類，不能讓單純日後還原必然卡在過期來源觀測，也不能全面取消撤銷、工具信任或目標重驗。保存時的 package 完整性不等於執行時資格永不失效。
- 決定性驗收：在來源 workspace 完成含 C/D/E、設定及空目錄的真備份，將交付集複製到獨立位置並核驗；於全新目標 workspace 禁用全部 source／舊工作區／原 UNC 存取，只帶交付集與必要工具材料完成 E3。測試替身一旦嘗試讀舊來源即失敗；不能只把 UI 的「來源離線」旗標設 true。

### 15.5 E3：新機勾選子集與離線原位置還原

- 匯入驗證後由同一 manifest／catalog 產生可還原清單。勾選單位以網站、排程、獨立資料範圍及支援設定為主，可下鑽檔案明細；不新增未定義的任意檔案編輯器。已確認備份集合預選可用項並允許取消，既有明確排除不自動復選。
- 選取的有效集合必須是備份核准與實際可用材料的交集；無 payload 的軟體只列補裝，未捕獲項不能靠勾選變可用。新增選取不擴大原備份授權。
- 必要相依自動提出並清楚標示「隨所選項必需」，在一次最終預覽中確認；使用者取消必要相依時，連帶 workload 標不完整並停止其執行，可保留獨立資料還原。共享檔案只寫一次，但所有已選 consumer 及未選受影響物件都須列明。
- Target receipt 綁備份集／generation／選取 revision／目前目標觀測與原位置；同一備份後續選另一合法子集不需來源重新在線或重封包，但需目標當下新預覽／確認。已完成項保留 journal，取消勾選不刪已還原檔案。
- 不沿用 NonC direct-transfer result 來假證明離線還原；C／NonC 都從備份 payload 寫新機原邏輯位置，並作 bytes／metadata readback。目標 disk／mount 身分與來源可不同，但不得偏離其已核准目標拓撲。
- 備份媒體所在路徑不得與目的還原範圍重疊或被自己覆蓋；缺磁碟、軟體、帳號、權限與原位置衝突逐項 deferred／blocked。目的地新安裝產物不自動覆寫。離線不免除目標本機重查。
- 相同 operation 重播只讀既有結果，真正的新選取建立新決策；未知提交 query-only。斷線／重開後恢復作業與已選集合，沒有秘密的項目可續作；待帳密項依 F4 處理。
- 驗收：僅 C、僅 NonC、混合部分選取、全部取消、共享相依、跨世代／錯主機 receipt、改選後續作、已有完成內容、來源完全不可存取；逐項讀回原位置且無未選寫入。所有必要卷先驗完整，不能靜默忽略未選項所在的缺卷而把整個備份稱完整。

### 15.6 F3：備份後完整 HTML 清單與新機操作頁

- 交付集提供可直接離線閱讀的 HTML 索引與本地資產，不依賴舊機 API、CDN 或網路字型；此靜態報告只讀。真正勾選與還原由新機啟動的本機工具 HTML 操作，不讓靜態 file:// 頁面直接執行還原或收帳密。
- 清單含全部已發現軟體、IIS／排程／資料候選與已確認備份範圍，每項有原位置、關聯工作負載、備份結果、未備份原因及已知必要補裝／人工工作。另列探索未覆蓋區域；「所有項目」不等於宣稱已發現未知資料。
- 所有列均可查閱；大量項目分頁／分段索引與搜尋，逐檔下鑽亦完整，不沿用列印最多 2000 列當清單截斷上限。摘要、清單、匯出、manifest 與新機選取來源使用同一識別；去重計數與 consumer 計數分開。
- 顯示「資料已備份」「獨立副本已驗證」「可還原條件」「業務可用」不同狀態。清單不能預先承諾未來新機軟體可用；新機匯入後補目前目標檢查。
- 驗收：獨立資料夾離線開啟、中文／空白路徑、超過現有列印上限且最後一筆可找到、空集合、部分失敗、偽造／錯包索引、HTML 注入字串；秘密不出現在安全投影。新機勾選實際改變正式 receipt 與 writer 集合，不只改畫面。

### 15.7 F4：帳密按需提示與耐久作業

程式核對：HtmlConsole 已有 Credential／Secrets 的 sensitive schema 與轉換；WizardRestore 已接受 Secrets，ServiceIdentity 區分內建帳號、ManagedServiceAccount 及 UserPassword。但這些參數存在不等於正式非同步 worker 已完成中途提示／安全交付；本階段需實查整條 UI→session→worker→native consumer，不假定已可用。

- 還原前盡量列出已知需要帳密的項目；按開始後可一次集中輸入已知需要值，後續才發現缺值時也能暫停並彈出 HTML 對話視窗。視窗顯示用途、對應項目與已核准帳號；不要求使用者理解 SecretRef。
- 同一已核准帳號／用途可在當次作業內經明確告知共用一次輸入，不能按帳號顯示名稱跨主機／用途自動共用。前端只在當前工作顯示提示；其他分頁或背景角色不能攔截該作業的秘密輸入。
- 只對需要 UserPassword 等明確模式的項目詢問；LocalSystem／內建服務帳號及支援的 gMSA 不索取不必要密碼。新帳號建立／帳號映射與輸入現有帳號密碼分開，改帳號屬授權資料變更，需重新預覽／確認，不可單靠 credential 欄位越過原核准。
- 缺值時記錄不含秘密的 WaitingForInput（名稱暫定）及所需欄位／項目／attempt；不可用普通 Failed 或 Succeeded 冒充。可取消或暫緩該相依組，獨立項按已確認集合繼續；清楚顯示部分結果。等待時不維持未完成的原生寫入或使整個工具死鎖，保留必要 ownership，喚醒後重驗目的狀態。
- 秘密只在當前可信本機 session／執行程序短期持有，不寫入備份、request/job/journal JSON、CLI 引數、環境變數、log、HTML 報告、localStorage／sessionStorage 或重連草稿；敏感值不經一般表單自動保存。需要跨 worker 程序時採具驗證、限本次作業且不落盤的交付機制；不能為跨程序方便而序列化密碼檔。
- 輸入提交綁 session、角色、Target、備份／選取 revision、operation／challenge；過期、另一頁／另一 Pair、已取消或已消耗的 challenge 拒絕。視窗關閉、完成、錯誤及程序終止後釋放可控制的敏感參照；不承諾可抹除瀏覽器／OS 的全部記憶體副本。
- 重啟可恢復進度但不恢復密碼；需要時重新詢問。錯密碼顯示受影響項及可重試原因，不無限自動重試以免鎖帳號；必要 OS API 保存服務／排程認證屬已明確授權操作，區別於工具自存秘密。
- 錯誤回應或網路斷線不能重新執行相同寫入；先查原作業／challenge。只有確認尚未接受且已重新核對有效挑戰時才重新輸入，不暗中重播原密碼。
- 驗收：真 HTML→正式 handler→正式 worker 的提示與續作；測密碼輸入取消、錯值、同帳號多 consumer、切角色、兩頁競爭、斷線、程序重啟及已完成項不重做。以合成秘密哨兵檢查所有持久材料與日誌零洩漏；帳密原生 consumer 可用窄型 fixture 隔離，不能據此宣稱企業帳號實測通過。

### 16.2 父作業、子階段與中斷續作契約

下列為語意狀態，名稱可依既有模型定案；不能新增多套互相矛盾的成功真相。父作業呈現一次使用者意圖，子階段／續作各有唯一執行識別與 lineage。原 request 及其結果不可改成另一份請求；後續 continuation 有自己的 idempotency key，但綁原父作業、已完成 checkpoint、核准及當前 revision。

| 階段／狀態 | 使用者可做什麼 | 中斷或恢復時必須如何判定 |
|---|---|---|
| 備份 Prepared→Capturing | 一次開始、查進度、取消 | 重啟先驗 owner／鎖與 journal；缺乏同一有效一致性範圍不能把新讀到檔案接進舊 generation。 |
| Captured→Sealing→Sealed | 查分卷／完整性結果 | publication 前的中間索引不得被 importer 視為完整；重啟驗已寫成員，未完成不覆蓋前份有效集合。 |
| Sealed→Delivering→IndependentCopyVerified | 查交付進度、重新選相同媒體位置 | 只複製／驗證 immutable bytes，可在來源業務已恢復時進行；不再凍結／讀取來源資料。最終「備份就緒」須同時具 Sealed 與有效交付證據。 |
| 還原 ImportedVerified→Selected→Previewed | 勾選、檢視相依、明確開始 | 只有單純顯示清單的 GET 不產生 receipt、不重盤點、不寫入；開始前正式 writer 重查必要條件。 |
| Restoring→WaitingForInput | 輸入帳密、暫緩該組、取消全作業 | 只在安全 checkpoint 等待。已完成項保留；等待不是 terminal CompletedUtc，不當成功，也不以無 CPU 進度判崩潰。 |
| WaitingForInput→Restoring | 回覆有效 challenge | 同 revision／帳號／授權不需再確認全部範圍；外部目標漂移則暫停並要求新預覽，不沿用舊確認。 |
| BrowserDisconnected | 關頁、重新開啟 | 只是觀察端失聯，活著的 worker 繼續或安全等待；重開查同一作業，不建立第二 writer。 |
| ProcessInterrupted | 開工具、檢視恢復預覽並續作 | 只有確認原 owner 已不存活且取得鎖才能接手；對帳 native／journal 後續作，需要的秘密重新輸入。不得自動回退或自動啟動業務。 |
| Deferred／Partial | 補裝、補磁碟／權限後續作 | 逐項重查，成功歷史不消失；父作業未達完整條件不能顯示全部還原完成。 |
| CancelRequested→Cancelled | 查看安全停止及來源恢復指引 | 取消即撤銷未消耗 challenge、停止後續可取消邊界；已開始不可原子取消的 native 操作先完成／對帳。晚到回覆不能復活，續作需新的明確 continuation。 |
| RestoreCompleted | 查看結果、另作啟用審閱 | 僅代表所選可執行還原集合及必要相依均完成 readback；不代表套裝補裝／業務驗收或啟用完成。 |

本輪不承諾任意中斷都能從同一位元組續傳；承諾不丟可驗 checkpoint、不誤成功、不覆寫不明內容，必要時明確重做尚未完成子段。選取在 Running／Waiting 期間不得靜默變更；要改選先停止原操作至安全狀態，再建立新 receipt／preview，先前已完成項繼續受 ownership 保護。

### 16.3 E3a：離線新機起步與比較材料閉合

1. 獨立交付必須附具相容工具取得方式、離線使用說明、被信任的來源核准材料與完整必要資料；新機不能為讀包要求連舊機下載 reader。工具本身須可信且版本吻合，不能直接執行包內任意程式。
2. 空 Target workspace 先由本機真實身分建立／確認 enrollment，再驗目標綁定 plan 並匯入；不複製來源或 Manager 的 workspace／lock／job 身分。此「空 workspace」是同一已核准目標主機的新工作區，不代表任意新硬體或重裝後身分改變可跳過重新授權。
3. 使用可信封存 source inventory／software catalog 與新機即時 target inventory，在新機正式核心入口產生當前比較及受限子集決策。此為新離線流程必要擴充；重用既有比較演算法，不能捏造舊 Manager 匯出或僅改 HTML 使其看似已核准。既有初始 Manager 核准仍是範圍上限，Target 的本機操作者只決定合法子集及已允許的新機準備事項。
4. 比較、receipt、preview 都綁相同 source bundle、目前 target snapshot、選取版本與 actor；補裝／重啟／重盤點後可在新機重新產生，不必回找舊 Source 或原 Manager 程序。增加來源集合、變更目標身分或超出初始核准的帳號／設定仍走正式新核准，UI 明列原因，不暗中擴權。
5. 獨立可信 hash／簽署／來源核准的取得與驗證須在 HTML 引導可操作，不能為免手填就從同一不可信包計算 hash 當授權。可由既有可信交接材料自動辨識，找不到時明列需補的材料與取得途徑。
6. 備份集的 read-only 匯入與清單檢視不宣稱 ProductionExecutionEnabled；缺企業執行資格仍沿既有 gate。未支援環境能看清原因及保留材料，不能讓「一鍵」繞過實際執行限制。

### 16.4 F4a／E3b／F4b：帳密、鎖與原生副作用

- 新能力需要修改完整狀態消費鏈：OperationRequests 狀態／返回碼、HtmlConsole worker 完成處理及 history recovery、WizardFlow／WizardRuntime／Restore 投影、UI polling／cancel／resume、結果報告。Waiting／Suspended 不填整個父作業 CompletedUtc；子 worker 完成可以有自己的時間。CLI 非互動缺值回傳可辨識等待／非成功結果，不讀隱藏輸入；互動 CLI 用相同 challenge 契約。
- HtmlConsole 現在使用同程序 PowerShell runspace 執行 worker；先以現有模型設計限作業的記憶體秘密交付，不無理由新增跨程序 broker。若實作必須改程序邊界，再以第 15.7 的不落盤要求驗證，不以規劃假定現有安全 IPC 已存在。
- 密碼回覆、查詢與取消是已存在父作業的受權控制訊息，不是另一個平行搬移 writer。等待時在安全 checkpoint 釋放執行用 OS／工作鎖，保留耐久資源 reservation／operation ownership；同一父作業可在該鎖內繼續獨立已選項。其他改寫作業不得藉等待搶占相同資源；續作須重新取得鎖、驗 owner／checkpoint／revision。這套接手／排他語意需同時涵蓋 UI 與 CLI。
- Challenge 的耐久部分僅含需求、綁定與 Pending／Accepted／Consumed／Revoked 等狀態（名稱暫定），秘密置於易失性儲存。若記錄 Accepted 後當機而值已遺失，可核對後發新 challenge；若 native 操作可能已執行，先讀 item journal／實際目標，不能直接再執行。兩者不可只用一個 boolean 表達。
- 新 session 明確接手等待作業後，舊 challenge／session 失效並重新發一個綁目前 session 的需求；舊頁不得回覆。檢視工作本身不接手，不為 GET 產生新挑戰或變更 owner。角色切換、同 workspace 第二個 console 與程序重啟均驗同一規則。
- 拒絕憑證和 unknown native outcome 分開：確定未套用才允許使用者更正密碼；可能已套用則使用 readback／對帳，無法證明時轉人工待查，不自動無限重試。不可為驗密碼額外發出無必要的登入探測，避免放大帳號鎖定。
- 服務／排程／IIS 身分模式的 credential consumer 列出預期權限及已核准身分，錯誤回覆不得包含密碼；應用私鑰、DPAPI 秘密、產品啟用資料等不假裝一個帳密視窗就能恢復。對不支援模式明列外部處理。
- 本機 secret endpoint 保留 loopback／Host／Origin／session 防護，POST body 限額與欄位白名單；敏感值不進 URL、request hash、error detail、telemetry 或回傳投影。UI 輸入為密碼欄位，成功送出／取消即清除；不要求或承諾全面清除 OS／瀏覽器內存。
- E3b 的 intent、實際寫入、readback、journal 完成各邊界要能重入判定；檔案、設定及帳號相關 side effect 不能共用「有同名物件就算完成」的捷徑。外部人改寫已完成目標則顯示漂移，不偷偷接管或覆寫。

F4a 是 prerequisite，不得先交付只有 UI 可輸入、後端不能接手的對話框。F4b 串上正式 handler／worker 後才開放使用者入口；原型 fixture 的成功不能當整段已交付。

### 16.5 D3／F3：交付、清單與來源停機判準

- 封存內容及靜態清單由同一已完成項目集合產生，兩者封存後不可改。外層交付索引記成員 hash，不能把含自身最終 hash 的報告循環放入自身 hash。獨立副本驗證收據引用已封存集合另存，不修改其 manifest／payload 來補「已驗證」標籤。
- 靜態 HTML 顯示擷取／封存當時狀態，明示不代表媒體目前仍完整；新機匯入會重驗 bytes。來源離線後的還原結果寫新機報告，不回寫來源備份。使用者不會因打開舊 HTML 就被告知目前還原已完成。
- 一鍵備份父作業涵蓋封存、交付、驗證；若獨立媒體待接入，顯示「等待交付」及下一步，不將父作業當成功。使用者外部手動複製也須經同一正式驗證入口，不能以「已複製」勾選替代逐材料核驗。
- 媒體重新定位以備份集身分、卷索引與 hash 綁定，路徑可以改，內容不可以換。首次完整核驗後的 resume 仍要驗必要成員未被替換；不能只信同磁碟代號或上次驗證時間。匯入過程缺媒體安全等待／中止，不能建立空成功結果。
- 單純顯示「獨立副本已驗證」只表示備份可取用，不授權關閉正在服務的舊機；來源當下運作／freeze／SourceResume、業務停機窗口及退役責任另列。使用者自行關閉舊機後的備份可還原性，是離線驗收要證明的能力，不由工具自動停機。
- 大量清單的離線查閱須在真 file:// 開啟驗證，不能只在 HTTP fixture 假定 fetch 本地 JSON 都可用；以不依賴該限制的靜態頁／索引策略實作。資料與 script 安全分離，長路徑／特殊文字不造成腳本執行；此為完整閱讀契約，不新增瀏覽器控制權限。

- 每個分頁標題顯示筆數；分頁內可搜尋名稱／路徑、依狀態或類型篩選；超過 2000 列時分頁或分段，且最後一筆找得到；可下鑽到檔案明細。三個分頁各自可匯出 CSV（UTF-8 BOM，方便 Excel 開啟；不含秘密）。
- 工作台 UI：
  - 採 WAI-ARIA tabs（`tablist`／`tab`／`tabpanel`、`aria-selected`、左右鍵切換、Home/End）。分頁記在 hash（例：`#jobs?filter=backup&tab=pending`），重新整理及返回都能回到原分頁。
  - 表格包在已命名、可聚焦的捲動區（沿用 `.table-wrap`），手機寬度可水平捲動。
  - loading／empty／error 各有自己的狀態；「尚未備份」與「零項目」分開顯示。
  - 沿用 `console.css` 現有 tokens（`--success`／`--warn`／`--danger`／`--line` 等），不引入框架或 CDN。
- 離線報告：
  - 以 file:// 直接開啟：不連網、不用 CDN、不用遠端字型，字型沿用 `system-ui, "Noto Sans TC", "Microsoft JhengHei"`。
  - 不 fetch 本地 JSON。資料用預先產生的分段靜態頁，或經 escape 的內嵌 inert 資料（`type="application/json"`）。JS 關閉時三個分頁改成三個區段依序顯示（漸進增強）。
  - 頁首標明「這是擷取／封存當時的狀態，不代表目前媒體或新機的狀態」（16.5）。不提供還原或帳密輸入（15.6）。
- 驗收：15.6 的原驗收全部適用，另外加上：
  - 已備份與未備份的聯集等於全部已發現項目，無重複、無遺漏。
  - 同一 ItemId 在工作台與離線報告的狀態相同。
  - 鍵盤可完整切換分頁。
  - 原生瀏覽器以 file:// 開啟並留截圖。
  - CSV 用中文版 Excel 開啟不亂碼。

### 18.5 F3-S：安裝軟體分頁與新機安裝檢查表

- 資料：C1 全來源軟體集合＋Inventory Roles（WindowsFeature）＋C2 使用者意圖，不另建盤點。
- 欄位：名稱、發行者、版本（未知就顯示「未知」）、架構、範圍（機器／使用者）、安裝位置、關聯工作負載、使用者決策（新機安裝／不裝／待定）、選用版本、人工備註（授權、需另行設定）。Windows 角色與功能放在獨立區段（IIS 子功能、.NET 等），附 `Install-WindowsFeature` 可用的名稱，只顯示、不執行。
- 分組：「已選工作負載必需」排在前面，其次是「其他已發現軟體」，兩組都可篩選。OS 內建項不混入（沿用 C1 規則）。
- 新機：工作台匯入備份集後，同一分頁增加「新機目前狀態」欄（已安裝／版本不同／未安裝／未知），由 E3a 的新機盤點比較產生。E3a 完成前不顯示此欄，不能用假值頂替。離線報告只有來源欄。
- 不提供安裝檔下載或自動安裝，也不承諾新版本相容（沿用第 1 節政策）。
- 匯出：CSV 及可列印檢查表；列印不在 2000 列截斷。
- 驗收：
  - C1 的反例（未知版本、雙架構、多帳號、權限不足、空盤點）在此分頁全部看得到。
  - 筆數與 C1 集合一致；角色與功能名稱與 Inventory 一致。
  - 新機狀態四種各有反例。

### 18.6 E3a-S：還原項目選擇，預設全選

定案：使用者執行還原時可以選擇要還原的項目，預設全選。此節補強 15.5。

- 預設：「可還原集合」（備份核准 ∩ 實際可用 payload ∩ 目標可放置）全部勾選。不可還原的項目（沒有 payload 的軟體本體、缺卷、需人工處理的目標衝突、超出核准範圍）照樣列出，但不勾選、停用並附原因，「全選」不會把它們勾進去。既有明確排除不自動復選（沿用 15.5）。
- 第二次以後的還原：預設全選「尚未成功還原」的項目；已還原的項目顯示狀態但不預勾。要重新還原已完成項目，必須明確勾選，並在預覽中另外確認。
- 勾選單位是工作負載（網站／排程／資料範圍／設定），可展開查看檔案明細。群組父項有三態（全選／部分／不選，用 `indeterminate`），並以文字標示「部分」。
- 操作：全選、全不選、依類型篩選後選取篩選結果。摘要顯示「已選 x／可還原 y，預計寫入 n 檔／b 位元組」，以 `aria-live="polite"` 更新。選取為空時「開始還原」停用並說明原因。
- 相依：使用者取消必要相依時，畫面立即標出受影響的工作負載，不自動改回使用者的選擇；預覽中顯示「不完整，此工作負載將停止」並要求確認（15.5）。
- 保存：選取 revision 存在 target workspace，重新整理或重開瀏覽器都保留；改選後需重新預覽（15.5）。
- UI：用原生 checkbox＋label，鍵盤空白鍵可切換，整個選取流程只用鍵盤就能完成。
- 驗收：
  - 初次預設勾選數等於可還原集合數；不可還原項不會被全選勾到。
  - 全不選時無法開始還原。
  - 部分選取後，receipt 與 writer 集合跟畫面一致（15.6 原要求）。
  - 重開瀏覽器後選取保留；第二次還原預設只勾未完成項。
  - 父項三態正確。

## 19. 第六次定案：還原端剩餘段落（F4a 其餘、E3b、F4b、G）

> 2026-10-20 依第 18.2 節順序接續還原端。本節只補現況核對、使用者定案與切段，不改第 15／16 節的契約。本節是規劃，不是完成證據。

### 19.1 現況核對（580e7f8）

- 帳密 challenge 只涵蓋 Service（`AccountMode=UserPassword`）。Password 排程與 SpecificUser 的 IIS pool 在計畫與審閱表單都無法帶 SecretRef，所以永遠無法核准；IIS pool 擷取時把 `processModel/@password`（IIS 加密字串）存進盤點與備份。
- 還原時排程／pool 若缺帳密，會先寫 `AssistiveAdapterIntent` 才失敗，留下 PendingOperations，之後整個父作業被擋到人工 Repair。
- `Get-WsmIisElementSnapshot` 會把 pool 的 `password` 屬性（Microsoft.Web.Administration 讀出的是解密後明文）收進 Before／readback 快照，再進 state 與 journal。
- 沒有通用續作：中斷的 TargetRestore 停在 Interrupted 沒有出口；只要有一筆 PendingOperations 就擋住整個父作業；舊 challenge 在改選或補裝後只會被拒，不會失效，新的還原反而被舊 challenge 卡住。
- 已有：同一父作業的 WaitingForInput、帳密端點與取消端點、以 ownership 判定已成功項不重寫、逐項對帳函式 `Complete-WsmAssistiveOperationRepair`、`sessionStorage` 的同分頁重開讀回與伺服器端 job 清單。

### 19.2 使用者定案（2026-10-20）

- F4b 的 HTML 帳密對話框套用 ui-ux-pro-max（原生 `<dialog>`、焦點管理、WCAG 2.2 AA、320px 寬度，沿用 `console.css` tokens）；E3b 的續作按鈕也併入同一次 UI 檢視。
- G 主旅程的原生帳號寫入（建立服務／排程／pool）以窄型 fixture 替身，檔案還原走真實原位置寫入與 readback；證據標明替身邊界，不宣稱企業帳號實測。
- 程序中斷後無法證明 native 結果的項目，只擋該項與它的相依項（IISSite→IISPool、Service→Service），其他獨立項照常續作；父作業為 Partial，不顯示全部完成。

### 19.3 切段與順序

F4a-2（計畫／審閱端讓排程與 pool 可帶帳密需求、盤點移除 pool 密碼）→ F4a-3（還原端 challenge 涵蓋三種 consumer、預覽標示、缺帳密不寫 intent、IIS 快照不含密碼）→ E3b-1（核心續作與逐項對帳）→ E3b-2（HTML／CLI 續作、恢復預覽、預覽漂移時撤銷舊 challenge）→ F4b（對話框與續作按鈕）→ G（主整合旅程劇本）。每段 Sonnet 5.5 subagent 實作，主代理審 diff、跑測試與突變後 commit／push。

### 19.4 明確不做

- IIS 站台虛擬目錄的 connect-as 密碼：維持既有拒絕，不在本輪接 challenge。
- IIS 組態區段的原始擷取（`RawEvidenceProtected`）仍保存整段 applicationHost 內容，可能含加密密碼；這是既有設計，本輪只記為未結事項，不改。
- 不新增跨程序秘密 broker；秘密仍只在同程序 runspace 的記憶體交付。
