起步

第一次使用：先確認主機與工作區

  1. 在本次指定的來源、管理或目標主機，使用核准版本的工具與 Windows 執行身分。一般入口使用 Windows PowerShell 5.1 或已受驗的 PowerShell 7。
  2. 指定固定的 WorkRoot，並依工作建立或選擇 PairId。畫面應清楚顯示目前主機、角色、工作區與配對；有任何一項不符就停止操作。
  3. 使用入口提供的本機 loopback 網址開啟工作台。網址只供該台主機當次程序使用，不轉寄、不公開，也不從其他電腦連入。
  4. 先看工作總覽，再從盤點與選取、軟體差異或檔案與路徑進入相符任務。沒有配對或資料時，依畫面列出的初始化與匯入步驟取得第一份可信材料。

以下是虛構的啟動格式示例；每台主機使用自己的固定 WorkRoot。這些命令只啟動本機工作台，不略過政策、不輸入核准或秘密，也不會自行執行移轉。

.\Start-ServerMigration.ps1 -Workspace 'C:\MigrationDemo\source' -Role Source
.\Start-ServerMigration.ps1 -Workspace 'C:\MigrationDemo\manager' -Role Manager
.\Start-ServerMigration.ps1 -Workspace 'C:\MigrationDemo\target' -Role Target

開始工作：前往「盤點與選取」 · 前往「操作中心」。

Windows Server Core、沒有可用瀏覽器或政策禁止 loopback 時，可使用同一版本提供的文字選單。它沿用相同核心與核准要求；不需要安裝瀏覽器、開啟防火牆或新增服務。

角色與責任

三種角色：操作位置由主機決定

Source｜來源主機

盤點來源、補充必要發現、核對原始路徑與設定，產生受信任的來源材料。保留原始 bytes 與證據，不在來源端代替目標操作。

Manager｜管理主機

建立配對、匯入來源與目標證據、比較差異、審閱選取與相依、處理責任分工、核准及產生交接材料。Manager 角色本身不代表可遠端執行目標主機操作。

Target｜目標主機

在目標本機取得最新盤點、準備軟體與路徑、檢查收據與預覽、執行獲准還原、讀回結果並提交階段證據。原生寫入必須在正確目標及權限下完成。

角色是操作上下文與導引，不是 Windows 登入或權限系統。真正可執行範圍仍由執行者身分、核心檢查與本次核准決定。多個瀏覽器視窗共用同一個本機程序的角色、配對與工作區。

常用任務

沿用具名操作逐步完成工作

來源：取得並保存可信材料

  1. 在來源主機執行 Inventory，指定輸出目錄並盤點主機、軟體、服務及工作負載；對無法可靠辨識的項目補充發現與責任說明。
  2. 檢查完整 IIS 設定、排程 XML 與安全設定、檔案範圍、C／非 C 分流和共享相依。未支援或無法解析的內容保留人工處置。
  3. 按畫面要求輸出受控材料並記錄路徑、SHA-256、來源主機與時間。Hash 用於確認 bytes 未變，不單獨證明製作者身分。回到盤點與選取。

管理：比較、審閱並核准

  1. 以 ImportInventory 匯入來源盤點檔及其必要的 ExpectedHash，依來源身分與 TargetName 建立配對；此動作只建立來源 catalog，不匯入目標盤點。目標人員另取得可信盤點並交給 Manager，由 Manager 以 TargetSnapshot 的 Path 與 ExpectedHash 更新該配對，再執行 PublishComparison。之後以 AssistiveEnable 初始化輔助盤點／選取，分開核對來源版本、選用版本與目標觀測。
  2. 透過 SaveSelection 保存選取；每個未選項目都要提供原因，再逐項處理相依影響、檔案 scope、生效路徑、帳號／SID、IIS／排程 typed 設定與人工責任。預設選取不代表核准。
  3. 預覽整個有效集合；核對必要項、共享資源與目標阻擋，再由有權責任人依既有流程核准。保存核准材料與交接所需證據。在操作中心執行具名操作。

目標：準備、還原與讀回

  1. 目標人員先在目標主機取得可信盤點，透過受控離線材料交給 Manager。Manager 在自己的工作區以 TargetSnapshot 提供檔案路徑與獨立 ExpectedHash 記錄目標快照，再執行 PublishComparison 發布比較；這不是目標主機本機操作，也不需先以來源 ImportInventory 匯入。僅重新載入舊比較不會重新盤點主機。
  2. 軟體須由責任人手動安裝；安裝或改版後重新盤點、比較並檢查相關收據是否仍有效。等待補裝不是安裝工作，也不是還原成功。
  3. 逐檔預覽衝突與原路徑／生效路徑，確認本次範圍及核准。明確確認後執行，再檢查 durable job、階段結果與實際目標讀回。
  4. 檔案成功、C 通道完成、非 C 通道完成、原生設定 readback、業務 staged、切換核准、啟用與 BusinessFinal 各自記錄。未取得證據的階段保持未知或待處理。查看操作表單與作業狀態。

對話式說明不會替你填核准、Owner、證據或確認欄位；不得以角色選擇代替執行者權限。進階操作仍可由完整清單到達。

名詞與狀態

用狀態文字判斷下一步，不猜成功

已觀測／快照
在指定時間取得的來源或目標資料。Assistive.Revision、DecisionRevision、currentSelectionRevision 是三個獨立原生 revision，不可相加成一個數字；dataVersion 是 fleet／catalog 實際 bytes 的摘要。sourceSelectionRevision 另供來源 SpecReview 綁定；current-selection revision 則供 UI CAS 使用。共同核對這些值、配對、主機指紋與取得時間，才能判斷是否為同一份目前資料。
選取／核准
選取表達本次意願；核准綁定特定來源、選取與材料。兩者不同，選取不能授權執行。
Pending／Deferred
仍有責任或條件未完成。Pending 不等於失敗或成功；Deferred 代表此刻保留處理，須依下一步重查。
Partial／Interrupted
部分項目已有結果或作業中斷。保留同一工作區、journal 與證據，先查權威工作紀錄和恢復預覽。
NotObserved／Unknown
目前沒有足夠的可信資料。不得由空白推論「沒有問題」或把未知轉成成功。
Activated／BusinessFinal
啟用與業務接受是不同階段。完成啟用不代表業務已接受；BusinessFinal 必須在啟用後由責任人提供實際證據。
ProductionVerified
產品及環境資格由獨立證據建立。fixture、隔離測試或單次檔案讀回不能代替企業實機與業務驗收。

只有指標有明確分子、分母、計數單位與涵蓋範圍時才可讀成比例。項目數、檔案數、C／非 C 結果和業務驗收不可混成單一成功百分比。

結果不明

提交逾時或斷線時，先查同一筆作業

  1. 記下畫面顯示的 OperationId、時間、配對與當時動作；不要重新建立相同操作或因逾時連按提交。
  2. 在建立作業的同一瀏覽器分頁重新載入後，回到「作業與交接」查詢 pending 工作與權威紀錄。這個分頁的 sessionStorage 只保存非秘密的作業 metadata，不保存表單草稿、token 或秘密；其他分頁不會共用這份 sessionStorage。
  3. 如果本機程序重啟後使用了不同 port，網址 origin 也已改變；瀏覽器不會自動帶回舊 origin 的追蹤 metadata。手動輸入已記下的 OperationId，或在完整作業歷史中尋找該工作。
  4. 若結果仍不確定，保留 WorkRoot、journal、輸出材料及錯誤識別碼，交由具權限者查核；不要猜測「沒有執行」後另送新 operation。只有權威紀錄確認可安全重試並依核心流程重新檢查後，才重新預覽。

讀取請求逾時可依提示重載；寫入請求逾時代表結果可能尚未確認。取消前端等待不會取消伺服端作業。不要把失去瀏覽器連線當作操作失敗或完成。

生命週期

關閉頁面、停止程序與取消工作是三件事

  • 關閉或重新載入瀏覽器頁面：只關閉或重新載入頁面，不會自動取消工作。表單草稿只存在記憶體，reload 後會失去；sessionStorage 僅保存非秘密的作業追蹤 metadata，不保存草稿、token 或秘密。建立作業的同一分頁重新載入後，可用它查 pending 工作；其他分頁不共用該資料。
  • 停止本機 PowerShell 程序：會停止該程序提供的本機工作台服務。執行中的工作可能記錄為 Interrupted；重啟後需先查 journal、操作紀錄及恢復預覽，不能假設背景服務仍在運作。若重啟後換了 port，請以 OperationId 或完整歷史找回工作，不會自動沿用舊 origin 的追蹤資料。
  • 取消工作：是向核心送出取消要求。只有工作到達安全取消點並記錄實際停止狀態，才代表取消完成；CancelRequested 仍是要求中。

共用程序是前提：同一台主機的多個工作台視窗共用角色、配對及工作區。追蹤 metadata 保存在建立作業的瀏覽器分頁 sessionStorage；同一分頁重新載入且仍使用相同 origin 時可用它查 pending，其他分頁及不同 origin 不會自動取得。草稿一律只在記憶體中，reload 後不保留。執行中已封存核准的作業須沿用核准時的原版工具 bytes，不可在作業中熱換工具；完成或安全結案後才依更新流程重新審閱。

時間與證據

快照呈現取得當時事實，不會持續更新主機狀態

來源盤點、目標快照、軟體比較、核准、收據與階段結果都有範圍與版本。Assistive.Revision、DecisionRevision、currentSelectionRevision 是三個獨立原生 revision，不可相加成單一數值；dataVersion 是 fleet／catalog 實際 bytes 的摘要。sourceSelectionRevision 另供來源 SpecReview 綁定；current-selection revision 則供 UI CAS 使用。共同核對配對、主機指紋、取得時間、三個 revision 與 dataVersion，才能判斷是否仍是同一份目前資料。

  • 「重新載入比較」只重讀或推導已保存材料，不會登入目標或重新盤點實機。
  • 更新目標觀測必須由目標人員在正確主機取得可信盤點，再以受控離線材料交給 Manager；Manager 在自己的工作區以 Path 與 ExpectedHash 執行 TargetSnapshot，然後 PublishComparison。ImportInventory 僅用於來源 catalog。
  • 更新軟體選用版本不改寫來源盤點事實；受影響的 comparison、receipt 或準備證據可能需要重新核驗。
  • Hash 可發現 bytes 改變；它不單獨證明來源可信、操作者身分、原生設定已生效或業務已接受。

報告與文件

報告會交由 Windows 預設程式開啟

工作台先核對報告參照及 hash，再把該檔案交給 Windows 預設程式。作業狀態 `Opened` 只表示已交由 Windows 開啟，不證明報告內容已顯示；預設程式可能另開視窗、使用既有視窗或其他關聯應用程式。若沒有看到報告，從受控工作區的報告位置重新開啟並確認 hash，不要把任意檔案路徑貼給 web 頁面。

教學頁與文件中心可另開瀏覽器頁面，提供離線閱讀；它們不建立新的角色或配對。可攜報告及證據資料夾需整份一起移動，保護來源清單、原始 XML、密碼與其他受控材料。

常見問題

遇到問題時保留證據，再採取下一步

工作台顯示錯誤主機或配對

停止提交。確認本機入口、角色、PairId 與 WorkRoot；若多視窗共用程序，先確認是否有其他視窗切換了上下文。

軟體版本不符或比較過期

由負責人手動準備軟體，取得新目標盤點，再發布比較。不要只更改畫面中的版本值就當成已安裝。

檔案或設定無法放置

查看逐項衝突、scope、consumer 與舊／新路徑。保留目的端既有內容，安排責任人檢查，不清空共用目錄、不合併既有文件，也不盲目改寫不透明 Arguments。

工作中斷或讀回失敗

保留同一工作區、journal、manifest 與來源材料。檢查失敗細節及恢復預覽後再選續跑、回復或交接；讀回未通過不能標成成功。

報告連結無法開啟

確認工作仍可存取、受控檔案存在且 hash 一致，再使用 Windows 預設程式開啟。不要編輯證據 JSON 讓 hash 通過。

業務仍無法使用

檔案與原生設定結果只是階段證據。由業務責任人確認身分、連線、排程、整合、監控、備份與實際流程，另行記錄 BusinessFinal 接受。

工具不自動安裝軟體、不新增遠端或常駐服務、不替你隱藏執行核准操作。遇到權限、正式資格或外部業務條件時，按組織的變更與交接流程升級處理。
